# SetuStock deployment and client pilot guide

This document is the deployment handoff for the current SetuStock release. The free-preview deployment configuration is included in commit `294da5a`.

## Recommended free pilot architecture

- Backend: Render Free Web Service
- Database: Supabase Free PostgreSQL
- Frontend: Vercel Hobby or Render Static Site

This setup is suitable for a client demo or small pilot. It is not yet suitable for production accounting data.

## Deploy the backend

1. Push the latest repository to GitHub.
2. Create a Supabase PostgreSQL project.
3. Copy the Supabase connection string as `DATABASE_URL`.
4. In Render, create a Blueprint from this repository. The included `render.yaml` deploys the Django backend from the `backend` directory.
5. Set these Render environment variables:

```text
DATABASE_URL=<Supabase PostgreSQL connection string>
CORS_ALLOWED_ORIGINS=https://<frontend-domain>
CSRF_TRUSTED_ORIGINS=https://<frontend-domain>
```

The following values are already defined by `render.yaml`:

```text
DJANGO_DEBUG=false
DJANGO_SECRET_KEY=<generated by Render>
DJANGO_ALLOWED_HOSTS=.onrender.com
SECURE_SSL_REDIRECT=true
SETUSTOCK_DEMO_MODE=false
```

The API URL will be similar to `https://setustock-api.onrender.com/api`.

## Deploy the frontend

1. Import the same GitHub repository into Vercel.
2. Set the project root directory to `frontend`.
3. Use `npm run build` as the build command and `dist` as the output directory.
4. Add `VITE_API_URL=https://setustock-api.onrender.com/api` before deploying.

The frontend already contains `vercel.json` so React routes continue working after a browser refresh. After the frontend URL is available, update `CORS_ALLOWED_ORIGINS` and `CSRF_TRUSTED_ORIGINS` in Render with the exact HTTPS frontend URL, then redeploy the backend.

## Client smoke test

1. Open the frontend URL in a private browser window.
2. Register one owner account from the registration screen.
3. Log out and log in again.
4. Open the owner dashboard.
5. Create or view a customer and product.
6. Create or view a quotation or order.
7. Open payments and create a demo payment link.
8. Confirm the API health/readiness endpoint.
9. Confirm logout blocks access until the user logs in again.

Do not hardcode a demo password in the repository. Share owner credentials privately and ask the client to change the password after first login.

## Current pilot limitations

- Render Free services sleep after inactivity, so the first request may be slow.
- Supabase Free has limited storage and can pause inactive projects.
- `EMAIL_BACKEND` is console-based by default. Password-reset and MFA emails will not reach the client.
- Do not enable MFA until SMTP, Resend or an equivalent email provider is configured.
- Uploaded files require external object storage; local free-service files are not durable.
- Free database services do not provide production backup and recovery guarantees.
- Use sample or pilot data until paid production infrastructure is configured.

## Production release checks

```bash
docker compose up -d --build
docker compose ps
curl -fsS https://api.example.com/api/ready/
```

Poll `/api/health/` for process health and `/api/ready/` for dependency readiness. For production, run `scripts/backup_postgres.sh` with PostgreSQL credentials and test restores in a separate database; never overwrite the primary database during a restore drill.
